**Goal:** 一次施工完成 spec 的 P12 与 P13(两项改的是同一批文件,合并执行):
① `runAgentLoop` 返回结构化 `stopReason`(end_turn / max_steps / aborted / error)+ usage/steps,**不再向调用方抛错**(spec D1,部分进度入史);wire `done` 扩展可选 stopReason/usage;App 在 max_steps 时显示提示条 + 「继续」按钮。

## 本计划新增决策(spec 未定,执行前定死)

| # | 决策点 | 结论 |
|---|---|---|
| D-P13-1 | 部分输出后还能不能重试 | **本次尝试已向 UI 发出任何 delta(emitted=true)则不重试、不降级,直接 error 收敛**。理由:text-delta 已进 reducer,重试成功会把同段文本双份追加,P14(seq/重放)之前客户端无去重能力。429/5xx/413 绝大多数发生在请求起步、零 delta,实际损失极小 |
| D-P13-2 | 与 AI SDK 内建重试的关系 | nodeModelClient 的 `streamText` 显式传 `maxRetries: 0`。loop 是唯一重试权威;否则 429 会 2×5 双层放大等待 |
| D-P13-3 | 重试常数的可测性 | `RunAgentOptions` 加可选 `retryBaseMs`(默认 500,**仅测试覆盖用**,生产不传);退避序列纯函数 `retryBackoffDelays` 独立导出单测 |
| D-P13-4 | 降级重发与重试预算 | 降级重发不占 retryable 的尝试预算;"每级至多一次/step"由投影单调性(normal→degraded→stripped 只进不退)结构性保证,无需计数 |

**Interfaces(Produces,后续任务逐字依赖):**

```ts
export type LoopStopReason = "end_turn" | "max_steps" | "aborted" | "error";

export interface RunAgentResult {
  messages: CoreMessage[];
  fullText: string;
  stopReason: LoopStopReason;
  usage: { inputTokens: number; outputTokens: number };
  steps: number;                  // 实际启动的 step 数(含出错/中断的那步)
  errorMessage?: string;          // 仅 stopReason === "error" 时存在,非空
}

export async function runAgentLoop(opts: RunAgentOptions): Promise<RunAgentResult>;
```

**背景(零上下文实现者):** 现 loop(`packages/agent-core/src/loop.ts`,141 行)返回 `{messages, fullText}`:maxSteps 耗尽静默结束、abort break、streamStep 异常发 error 事件后 **rethrow**。本任务四值收敛,判定规则(spec C12-1/C12-2):

- `end_turn`:某 step 的 `toolCalls.length === 0` 自然收束(loop.ts:85 的 break 点)。
- `max_steps`:for 循环因步数耗尽退出(此时最后一个 step 必有 toolCalls,否则早已 end_turn break——该蕴含关系即 C12-2)。
- `aborted`:三处 abort 路径(循环顶 `signal?.aborted` break、工具循环中 break+I-1 补齐、**streamStep 因 abort 抛出**——catch 里 `signal?.aborted` 为真时归此,不发 error 事件)。
- `error`:catch 且 `!signal?.aborted`。发 error 事件(现状保留)后**不再 rethrow**;已积累的 `stepText` 非空时以 `{ role: "assistant", content: stepText }`(**无 toolCalls**——本 step 浮出的 toolCalls 未执行,带上破坏配对不变量 C12-5)入史;设置 `errorMessage`。

调用方兼容:server/agent.ts:190 与 app/useAgent.ts:344 都只解构 `{ messages }`,扩展返回值不破坏编译;它们的 catch 分支语义在 T5/T7 处理。**本任务不动 catch 的分类逻辑**(classifyError 是 T4 的事),catch 只按 aborted/error 二分——T4 在此 catch 内插入重试/降级分支。

const BASE_DELAY_MS = 500;
const MAX_DELAY_MS = 32_000;
const FACTOR = 2;
const JITTER = 0.25;

export function retryBackoffDelays(maxAttempts: number, baseMs = BASE_DELAY_MS): number[] {
  const count = Math.max(maxAttempts - 1, 0);
  const delays: number[] = [];
  for (let i = 0; i < count; i++) {
    const base = Math.min(baseMs * FACTOR ** i, MAX_DELAY_MS);
    delays.push(base + Math.random() * JITTER * base);
  }
  return delays;
}

export function abortableSleep(ms: number, signal?: AbortSignal): Promise<void> {
  return new Promise((resolve, reject) => {
    const abortErr = () => new DOMException("The operation was aborted.", "AbortError");
    if (signal?.aborted) { reject(abortErr()); return; }
    const timer = setTimeout(() => { cleanup(); resolve(); }, ms);
    const onAbort = () => { clearTimeout(timer); cleanup(); reject(abortErr()); };
    const cleanup = () => signal?.removeEventListener("abort", onAbort);
    signal?.addEventListener("abort", onAbort);
  });
}
